# Срокове и глоби (Task Deadlines & Fines)

Система за управление на задачи, срокове и автоматични глоби при неоснователно
закъснение, с известия по Telegram, Slack, Email/Gmail, WhatsApp, Viber и
Google Calendar.

Как работи накратко:

1. Администратор създава задача с ясен срок (deadline) и приоритет за
   конкретен служител.
2. Служителят получава известие веднага, и напомняне `REMINDER_HOURS_BEFORE`
   часа преди срока — по всеки канал, за който има зададени данни.
3. Ако срокът мине и задачата не е маркирана като завършена, системата
   автоматично: маркира я като просрочена, начислява глоба по конфигурируемо
   правило (толеранс + базова сума + сума на ден закъснение) и уведомява
   служителя на всички налични канали.
4. Ако закъснението е било основателно (болест, форсмажор и т.н.),
   администраторът анулира глобата с обяснение — служителят получава
   известие и за това.

## Структура

- `server/` — Node.js/TypeScript API (Express + Prisma + SQLite), cron
  job за проверка на срокове, адаптери за всеки канал за известия.
- `web/` — React/TypeScript табло (Vite): задачи, глоби, служители, настройки.

## Първоначално стартиране

### Backend

```bash
cd server
npm install
cp .env.example .env      # виж по-долу за попълване на данните за всеки канал
npx prisma migrate deploy
npm run seed               # създава admin@example.com / ChangeMe123!
npm run dev                 # http://localhost:4000
```

### Frontend

```bash
cd web
npm install
cp .env.example .env        # VITE_API_URL сочи към backend-а
npm run dev                  # http://localhost:5173
```

Влез с `admin@example.com` / `ChangeMe123!` (задай истинска парола след
първия вход) и създай реалните служители от таб „Служители“.

## Задачи, срокове и глоби

- Всяка задача се създава от администратор с краен срок и приоритет
  (Low/Medium/High/Critical).
- Правилата за глоби („Настройки“ → „Правила за глоби“) определят:
  - **Толеранс (часове)** — период на изчакване след срока, преди да
    започне да тече глоба (напр. 2 часа буфер).
  - **Базова сума** — глобата при първо просрочие.
  - **Сума на ден** — добавя се за всеки следващ ден закъснение.
  - **Максимум** — таван на глобата за една задача.
  - Може да зададеш отделно правило за приоритет „Критичен“, за да
    санкционираш по-строго закъснения по важни задачи.
- Cron job-ът (`SCHEDULER_CRON`, по подразбиране на всеки 5 минути) проверява
  всички отворени задачи, маркира просрочените и начислява/ескалира глоби.
- Глоба, наложена автоматично или ръчно, може да бъде анулирана
  („Глоби“ → „Анулирай“) с текстово обяснение — това е механизмът за
  „основателно закъснение“.

## Настройка на каналите за известия

Всеки канал е самостоятелен — активирай само тези, които ти трябват.
Статусът им се вижда в таб „Настройки“ на таблото (показва дали сървърът
има зададени данни, не дали конкретен служител е свързан).

За всеки служител в „Служители“ → „Редактирай“ въвеждаш неговия конкретен
идентификатор за канала (chat ID, телефон и т.н.) — известията отиват само
по каналите, за които служителят има зададени данни.

### Telegram

1. Отвори чат с [@BotFather](https://t.me/BotFather) в Telegram, изпрати
   `/newbot` и следвай стъпките — ще получиш токен.
2. Сложи токена в `server/.env` като `TELEGRAM_BOT_TOKEN`.
3. Всеки служител трябва да си отвори чат с бота и да изпрати `/start`.
4. За да намериш неговия `chat_id`: служителят пише на бота, после отвори
   `https://api.telegram.org/bot<TOKEN>/getUpdates` в браузър — ще видиш
   `chat":{"id": ...}` в отговора. Сложи това число в профила на служителя.

### Slack

Най-лесно — Incoming Webhook (известията отиват в един избран канал):

1. https://api.slack.com/apps → Create New App → From scratch.
2. Activate Incoming Webhooks → Add New Webhook to Workspace → избери канал.
3. Копирай URL-a в `server/.env` като `SLACK_WEBHOOK_URL`.

По избор — директни съобщения до всеки служител вместо общ канал:

1. В същото приложение добави OAuth scope `im:write`, `chat:write`,
   `users:read` и инсталирай в workspace-а.
2. Копирай Bot User OAuth Token (`xoxb-...`) в `SLACK_BOT_TOKEN`.
3. За всеки служител вземи неговия Slack Member ID (профил → „Copy member
   ID“) и го сложи в „Служители“.

### Email / Gmail

1. Включи 2-факторна автентикация на Gmail акаунта.
2. Създай „App password“: https://myaccount.google.com/apppasswords
3. Попълни в `server/.env`:
   ```
   SMTP_HOST=smtp.gmail.com
   SMTP_PORT=465
   SMTP_SECURE=true
   SMTP_USER=твоя_имейл@gmail.com
   SMTP_PASS=генерираната app password
   ```
4. Всеки служител автоматично получава известия на своя имейл (полето
   `email`, задължително при създаване на профила му).

### WhatsApp (Meta WhatsApp Cloud API)

1. https://developers.facebook.com/ → създай App → добави продукт
   „WhatsApp“.
2. От „API Setup“ вземи временен Access Token и Phone Number ID (за
   продукция — генерирай постоянен токен през System User).
3. Сложи ги в `server/.env` като `WHATSAPP_ACCESS_TOKEN` и
   `WHATSAPP_PHONE_NUMBER_ID`.
4. Всеки служител трябва първо да е писал на бизнес номера (WhatsApp
   Cloud API изисква предходен контакт/шаблон за първо съобщение извън
   24-часовия прозорец — за продукция ще трябва одобрен темплейт).
5. Въведи номера на служителя (в международен формат, без `+`, напр.
   `359888123456`) в неговия профил.

### Viber (Viber REST Bot API)

1. https://partners.viber.com/ → Create Bot Account → вземи Auth Token.
2. Сложи го в `server/.env` като `VIBER_BOT_TOKEN`.
3. Служителят трябва да намери бота (по линк/QR от Viber admin панела) и
   да натисне „старт“ поне веднъж — едва тогава Viber дава `user id`.
4. `user id`-то идва в webhook събитие при първия контакт (за пълна
   автоматизация в продукция се добавя webhook endpoint; за начало може
   да се вземе ръчно от Viber Bot admin панела → раздел „Subscribers“).
5. Сложи го в профила на служителя.

### Google Calendar

Известията тук се материализират като събитие в календара с popup
напомняния (1 час и 24 часа преди срока) — вместо съобщение, служителят
вижда блокирано събитие в графика си.

1. https://console.cloud.google.com/ → нов проект → Enable API →
   „Google Calendar API“.
2. „APIs & Services“ → „Credentials“ → Create OAuth client ID → Web
   application, с redirect URI `http://localhost:4000/api/integrations/google/callback`.
3. Копирай Client ID / Client Secret в `server/.env`.
4. Еднократно получи refresh token чрез OAuth Playground
   (https://developers.google.com/oauthplayground): настрой го да ползва
   твоя Client ID/Secret (иконата зъбно колело горе вдясно), избери scope
   `https://www.googleapis.com/auth/calendar.events`, оторизирай със
   акаунта, чийто календар ще приема събитията, и вземи refresh token от
   стъпка 2.
5. Сложи го като `GOOGLE_REFRESH_TOKEN`.
6. По избор — попълни `googleCalendarId` в профила на служителя, ако
   искаш събитията да отиват в конкретен негов календар, а не в
   „primary“.

## Тестване на известията

В „Служители“ → бутон „Тест известие“ праща тестово съобщение на избрания
служител по всички канали, за които има зададени данни — вижда се резултат
за всеки канал (SENT/FAILED/SKIPPED и причина при грешка).

## Тестове

```bash
cd server
npm test
```
